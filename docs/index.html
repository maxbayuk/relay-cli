The Problem

Relay's API has 47 endpoints across 80+ chains. AI agents and developers are bad at using it directly.

4 core pain points that cause AI agents to hallucinate or fail when calling Relay's API:

1. Response shape mismatch — {"chains": [...]} wraps the array, but agents assume a bare array.
2. Nested arrays — solverAddresses is an array per chain, not a string. Agents do string comparison and get nothing.
3. Spec bloat — The OpenAPI spec is 954KB with zero reusable schemas (everything inlined). Too large for context windows.
4. No introspection — Agents guess at field names and response shapes instead of querying them.

Inspired by Google Workspace CLI, which dynamically generates its entire command surface from Google's Discovery Service. The relay-cli applies the same pattern to Relay's OpenAPI spec — zero hardcoding for endpoint discovery.

📋 Schema Introspection

Agents can query response shapes at runtime instead of guessing. Replaces the need to stuff the full 954KB spec into context.

relay schema chains # response shape for GET /chains relay schema quote.v2 # request body schema for POST /quote/v2 relay schema --list # all 29 public endpoints

🔍 Field Filtering (Context Window Protection)

JMESPath expressions shrink responses to only what's needed. Built-in presets for common patterns.

# 350KB chains response → ~2KB relay chains list --fields "chains[].{id: id, name: name, display: displayName}" # Built-in presets relay chains list --preset slim # id, name, displayName, vmType, depositEnabled relay chains list --preset health # id, name, disabled, blockProductionLagging

🖥️ Smart Output Detection

Auto-detects terminal type: table output for humans (TTY), JSON for scripts/agents (piped). No flag needed.

⚡ Smart Aliases

Hardcoded shortcuts for the most common operations. These take priority over dynamic commands.

relay status 0x123... # → GET /requests/v2?id=... relay tx 0x123... # → prints relay.link/transaction/... URL relay bridge --from base --to eth # → resolves + POST /quote/v2

Safety Guards

Execute endpoints (/execute/bridge, /execute/swap) require the --confirm flag. This prevents AI agents from accidentally submitting live transactions. Without it, the command errors with a clear message.
DECISION POINT — EXECUTE SAFETY MODEL
Require --confirm flag

Agent must explicitly opt-in to execution. Dry-run is always available. Fail-safe default.

Interactive confirmation prompt

Works for humans but breaks agents. Non-TTY environments can't respond to prompts.

Auth & Config

API Key Resolution Priority

resolveApiKey()
1. CLI flag --api-key — highest priority
2. Environment variable RELAY_API_KEY — for CI/Docker
3. Config file ~/.relay-cli/config.json — persistent, 0o600 perms
4. No key — anonymous requests (some endpoints are public)
# Set API key relay config set apiKey your-key # Or use environment variable export RELAY_API_KEY=your-key # Switch to testnet relay --testnet chains list
